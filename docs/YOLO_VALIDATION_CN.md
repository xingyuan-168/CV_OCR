# YOLO v26 候选验证报告

这是上一0.14.5/协议26候选的历史实测记录。最新0.14.6/v23.6必须用新二进制重新验证，交付进度及本轮数据见[v23.6交付说明](V23_6_DELIVERY_CN.md)。

本报告验证源码实现与当前 Windows 主机上的公共调用链。**E5-2696 v4 / RTX2070 五窗口的 P50≤20ms、P95≤30ms 验收尚未完成**；本机没有 NVIDIA GPU，不能以编译成功代替 TensorRT 执行、FP16 精度或 CUDA Graph 验收。

## 环境和基线

- 本机：i7-13620H，10 个物理核、16 个逻辑处理器，Intel UHD Graphics；另有虚拟显示设备。
- 产品运行库：ONNX Runtime 1.24.4 / DirectML 1.15.4。Python 安装的其他 ORT 版本未用于产品测量。
- 模型：`input/best.onnx`，静态 FP32 `[1,3,320,320]` → `[1,10,2100]`，六类，12,143,093 字节。
- 模型 SHA-256：`ca5407763a638b86d73e9f17c423ebec39c9b0c8c1ee7f33de64aa32c73177b8`。
- 800×600 BMP SHA-256：`b7af17048105355f3ca3c636663a867ad29953ab3162be19dc0005fcee688d6d`；conf0.5，NMS0.45。
- 原版 x64 DLL 在修改前保存；原版 x86 DLL / Worker 从未修改的正式 v23.5 ZIP 提取。候选使用协议26独立管道，旧版使用协议25；两者没有混用。

## 完整调用性能

五个调用线程共享一个句柄，每线程预热100次、正式采样1000次，独立三轮。QPC 从 `YOLO_InferJson` 入口计到结果返回；正式采样关闭逐帧诊断和 ORT profiling，各候选顺序运行。下表取三轮所有单路指标的最大值，单位 ms。

| 实现 / 调用模式 | 每 Session 内部线程 | P50 | P95 | P99 |
|---|---:|---:|---:|---:|
| 原版 x64 / 持续 | 3 | 19.212 | 26.256 | 30.358 |
| 原版 x64 / 同时发起 | 3 | 21.827 | 25.749 | 28.291 |
| 候选 x64 / 持续 | 2 | 22.963 | 28.491 | 30.767 |
| 候选 x64 / 同时发起 | 2 | 24.196 | 28.033 | 30.062 |
| 原版 x86 / 持续 | 3 | 24.343 | 30.237 | 32.993 |
| 原版 x86 / 同时发起 | 3 | 21.714 | 127.876 | 133.221 |
| 候选 x86 / 持续 | 2 | 25.709 | 30.080 | 31.908 |
| 候选 x86 / 同时发起 | 2 | 25.165 | 28.905 | 31.160 |

原版 x86 在 CPU 上也出现约125ms长尾，源码中逐请求连接及 `Sleep(100)` 重试可以造成这类延迟；候选长连接消除了本机测试中的该长尾。它支持“130ms不能直接归因为GPU计算”的判断，仍不能证明目标机45/130ms的具体组成。

CPU 的 P50 未提速且未达到目标。原版按逻辑处理器配置3线程，候选按物理核预算配置2线程，两种配置的资源占用不同；本机混合核心CPU结果不能外推到E5。完整报告记录每路及整体分位数、吞吐、CPU核当量、内存、加载时间、实际后端和DLL/Worker/模型哈希，位于 `outpush/yolo-validation/*-continuous.json` 与 `*-simultaneous.json`，另附原始 samples/resources CSV。

八组正式报告共120,000次调用无失败，检测 JSON 与各自顺序参考一致；四条产品路径的基线图片检测结果也完全一致。

## 阶段诊断和校准

候选 x86 的550条调用按请求ID关联：打包/连接/收发合计 P95 **0.867ms**，预处理 P95 **0.490ms**，后端执行 P95 **23.553ms**，后处理 P95 **0.044ms**。本机通信低于2ms门槛；共享内存未启用，目标机仍需重新测量。

Worker 正常退出会截断诊断文件的尾部缓冲；汇总忽略了一个残行。调用方文件包含全部550条返回的Worker阶段数据，因此关联结果完整。正式性能报告未启用该诊断。

DirectML profiling 在Intel UHD单 Session、单调用线程的七次执行中记录七个 `DmlExecutionProvider` 节点事件，没有可见CPU节点或 memcpy事件。融合后的provider内部复制无法从该日志单独计量；此结果不能代表RTX2070节点分配。

离线工具已扫描物理核预算允许的1/2/4/6/8内部线程与1/2/3/5 Session组合，使用基线图和三张YOLO测试图，CPU检测数据完全一致。该扫描为短样本功能验证，不能用其分位数宣布达标。业务记录AUTO回读、x86记录跨x64使用、中文校准路径均已验证。没有发布FP16或Graph记录。

## 正确性及稳定性

- x64矩阵19项、x86矩阵22项：完整回归与受影响项目复测均通过；首次参数报错文字兼容失败已修复，原始及复测日志保留。
- 新增预处理测试对五种格式、正负stride、800×600、奇数尺寸及极端宽高逐浮点位比较旧算法；BMP方向、padding、长度/溢出检查通过。
- YOLO传输测试通过：长连接、请求ID、超长帧、半帧断管、Worker重启/旧句柄、并发释放、模型加载失败后CPU重试，以及不同模型加载参数独立于Worker启动环境。GPU槽数不受CPU线程预算误拒绝。
- 现有多模型、空结果、阈值、OCR/CV、ANSI路径及OCR CPU/DirectML/AUTO回归通过。
- Python绑定5项与校准精度/Graph/选择规则6项通过。
- 五路变化帧CPU稳定性运行1800.023秒，四张图片轮换，共348,942次调用、零错误；逐次返回JSON与各图片的顺序参考完全一致，无死锁或请求错配。
- 该稳定性运行的整体P50/P95/P99为25.868/30.326/32.278ms，吞吐193.854次/秒；最差单路P50/P95为25.894/30.357ms。运行期间还执行了候选打包及安装检查，此项用于稳定性验证，正式性能比较以此前三轮独立测试为准。
- 从第120秒起，调用方private memory保持115.469–115.617MiB，结束与起始差0MiB；Worker保持210.855–210.945MiB，结束较起始低0.023MiB，未出现持续增长。报告为`soak-x86-30min.json`、`soak-summary.json`及resources CSV。
- 候选Python Wheel已在全新虚拟环境中安装，OCR/CV、多模型YOLO回归通过；`AI_DEVICE_TENSORRT=3` 可用，缺驱动返回明确的 `nvcuda.dll is missing` 错误。
- 候选65个文件与已测试原生DLL/Worker哈希一致，两个基础ZIP的CRC与成员SHA、Wheel原生文件SHA均通过；可选NVIDIA包25个清单文件及TensorRT/CUDA/VC许可完整性通过。公开函数保持60个；x86仍保留原有60个stdcall别名。可选模块仅依赖bcrypt、VERSION、KERNEL32系统库。

## NVIDIA与目标机待验

可选模块使用官方TensorRT10.13.3.9、CUDA12.8 Update1头文件编译。其依赖为Windows系统库，CPU/DirectML启动没有NVIDIA运行库依赖；缺驱动时显式TensorRT返回具体错误。各执行槽独立context/stream/buffer，共享engine，FP32输入输出，FP16和Graph须先通过业务校准。驱动文件版本及SHA参与engine缓存，实际驱动更新也会使缓存失效。

以下必须在目标机实测：TensorRT FP32执行与缓存命中/损坏重建；FP16对现有及五窗口业务图片的数量/类别/坐标/分数门槛；1/2/3/5 context选择；Graph捕获和每轮P95≥10%收益；显存/驱动；五窗口30分钟GPU稳定性；每路完整调用P50≤20ms、P95≤30ms。目标通信P95若仍>2ms，再实现共享内存图像槽。

候选包、工具、易语言QPC示例和可选NVIDIA依赖仅输出到outpush。正式 `release/v23.5` 成品未晋升或修改。部署与目标机命令见 [优化说明](YOLO_OPTIMIZATION_CN.md)。
